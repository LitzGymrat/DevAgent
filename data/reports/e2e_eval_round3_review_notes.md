# Round3 端到端评测与人工复核纪要

**时间**：2026-03（向量库重建后复测）
**范围**：全量 90 条；E2E 与 **index-aware Judge** 对齐当前 `e2e_manifest`（含 `grounding_tier_index_aware`）。

## 0. 阶段总括（小仓库阶段）

**本阶段已完成的关键验证包括：**

1. 前置 Prompt / Tool Schema 约束可显著降低无效检索；
2. 后置软熔断可作为低质量召回的保底机制；
3. 分桶评测能够有效区分通用问题稳定性与域内 grounded 风险；
4. index-aware Gold 与人工复核对定位真实 bad case 具有必要性。

结合前置工具策略、软熔断、分桶评测与人工复核，当前可作如下归纳（**不限于 Round3 单次数字**）：

| 维度                                               | 结论                                                                                                                               |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **前置边界**（何时可调 `search_codebase`） | 约束显著后，**误调用（FP）明显减少**，是第一层主收益来源。                                                                   |
| **后置软熔断**                               | 作为**兜底** 有效，能处理弱召回；但整体体验上 **不是主收益来源**（且子集规模随 FP 减少而缩小）。                       |
| **far_general / term_near / misleading**     | **表现稳定**，与「少查库、少绑仓库」的设计一致。                                                                             |
| **domain 桶**                                | 问题一部分来自**grounded 不足**（模型/链路），一部分来自 **评测噪声**（gold/索引/Judge，见 §3）。                     |
| **LLM-as-Judge**                             | 无全库 context，仅见题干+日志+截断回答；在**tier 边界的执行** 与 **通识/仓库细节** 的区分上存在 **方差与局限**。 |

**阶段判断**：在 **当前小仓库** 上，**机制验证**（前置决策 + 软熔断 + 分层 gold + index-aware）已基本闭环；**继续在同一尺度上反复 rerun**，主要会撞上 **评测噪声与标签争议**，ROI 偏低。

**更高 ROI 的方向**：**暂停**为微调数字而无限重跑；将精力转向 **更大仓库、更复杂分布** 的场景，在真实难度下再评估是否引入 **数据飞轮** 与 **DPO**（需更大规模、更可验证的偏好对，见讨论结论）。

## 3. 人工复核结论（bad case 归因框架）

对 Judge 标出的 bad case 逐条复核后，**错误并不都能归因于模型能力不足**，而常见由下列 **四类因素** 共同作用：

1. **真实的 grounded failure**检索侧已有可用证据时，回答仍未按仓库事实作答，或与代码明显矛盾（优先视为 **模型 / Agent 工具链路** 问题）。
2. **题面或 gold 与实现不对齐**题干指向的实现缺失、占位、或仍被标为 `must_ground`，导致「按标注应 grounded、按仓库却无可稳锚定内容」的 **结构性矛盾**（**评测集 / 标注** 问题）。
3. **证据不在当前索引范围内**相关代码不在 `src/` 建库范围、或未进入向量 chunk，客观上无法检索到片段，却仍按 `must_ground` 评判（**建库范围 / 索引** 问题，不宜单怪模型）。
4. **Judge 对「是否显式写出路径/符号」过于敏感**
   回答已实质利用检索内容时仍判「未锚定」，或对合理推断一律否定，存在 **误判与措辞过重**（**第三层 Judge** 校准问题）。

## 4. 后续原则

- 优化与数据迭代时，**先区分「模型问题」与「评测问题」**，避免将（2）（3）（4）中的噪声 bad case **误当作主训练信号** 回流。
- 全链路对比须注明：**索引更新会同时改变检索与回答**，新旧结果宜表述为「同一 benchmark 下的前后复测」，而非单一变量控制实验。
