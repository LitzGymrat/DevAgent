> **可直接展示**：[12-咨询展示-展示版.html](./12-咨询展示-展示版.html)（内嵌数据表，适合投屏）。  
> 下列三点对应我们**一步步做出来**的主线；细节与复现见 `评估/08–11` 与仓库脚本。

## 关键点一：检索侧闭环 — 软熔断、bad case 驱动的 Prompt、效果评测、LLM-as-Judge

**脉络**：先承认「会过检索」——用 **Dense 距离分桶 + 阈值**（软熔断 Phase1）把问题**量化**；发现单靠距离**切不干净**，软熔断更适合做**误调检索之后**的兜底。再拉 **端到端**（`search_codebase` + 可选软熔断），用 **bad case** 反推：首轮第一层 **FP 很大**，根因在 **Prompt / 工具描述**，于是做 **Prompt engineering**（system + `search_codebase` 描述），复测后第一层一致率 **63.3% → 97.8%**，**FP 33 → 2**。最后补 **LLM-as-Judge** 作为**系统评测第三层**：回答好不好不能只看「调没调工具」，用 **分层 rubric（bucket + grounding_tier）** 评最终回答，并把 **索引是否滞后** 与 **模型策略** 分开讨论。

**一句话**：先量后治；**策略（Prompt）治本，软熔断兜误调后的检索质量**；Judge 补齐「答得怎样」。

## 关键点二：大仓库迁移 + 数据飞轮 + 微调 — 首轮落在路由；后续还有检索后生成与偏好对齐

### 「大仓库迁移」在这里指什么（建议对外讲清楚）

**不是**一句抽象口号，而是三层含义，我们**分开落地**：

1. **评测与产品语境**：从「小 demo 仓好搜」迁到 **真实大代码库尺度下的行为** —— 检索更噪、过检索/欠检索都更致命，所以需要 **软熔断、grounding 分档、E2E 分桶**，而不是只在干净小库里报高分。  
2. **工程基准（可复现的大仓）**：在 `experiments/external/` 用 **pin 过的上游克隆**（默认 **Transformers + FastAPI**，blob **不进主仓 git**）做大仓基准；与主工程用于日常开发的 **`src/` 向量索引**（`data/chorma` 等）**刻意隔离**，避免把「玩具索引」误认为大仓表现。实验用索引可走 `experiments/indices/`（见 `experiments/README.md`）。  
3. **数据与微调语境**：数据飞轮里的 **私域切片**（FastAPI+Transformers 等）是在 **模拟「大仓库里的典型研发任务」**；**远域 / 误导** 切片则压「不该乱查私库」 —— 这和第 1 点的评测设计是 **同一条故事线**，不是另一套无关数据。

**一句话**：**大仓库迁移 = 评测口径对齐真实规模 + 外部大仓基准可复现 + 训练/场景设计跟这条线对齐**；路由 SFT（Phase 2A）先把 **决策** 做对，再谈检索后生成与 DPO。

---

**数据飞轮**：按微调目标 **生成多样化、带配比** 的场景数据（私域 / 远域 / 误导比例可调）；**重视质量** — **机器过滤**（规则与自动化审计）+ **人工抽样复核**（清单与 review 导出）。再 **ShareGPT → LLaMA-Factory** 训练。

**第一轮 SFT（Phase 2A）落脚点**（你已定型）：**工具路由**、**JSON 格式稳定**、**决策准确度**（`tool_call` / `no_tool` / `clarify_needed`）；**不**把「参数与金标逐字一致」当主 KPI。定量评测用自研 **`eval_*_phase2a`**（Base / LoRA / API），50 条上 LoRA 相对基座在 decision 与格式上提升明显。

**后续打算**：在路由对齐之后，再考虑 **检索后生成质量** 的微调；**语言风格 / 偏好** 一类目标上，有 **DPO**（或同类偏好优化）的打算，与纯路由 SFT **划界**推进。

---

## 关键点三：前沿思路的采用计划 — RAGAS 启发式评测、Self-RAG 启发式后训练

**评估**：计划借鉴 **RAGAS** 一类 **启发式指标**，在**召回之后**对回答质量做更系统的度量（与现有 E2E + Judge **互补**，不追求替代人工 gold，而是可回归、可扩展）。

**训练**：计划借鉴 **Self-RAG** 的思路做 **后训练**，侧重 **工具调用链上的反应与自省**（何时检索、何时信检索结果、何时拒答或澄清），目标包括提升 **工具调用的反应速度与决策质量**（具体形态随实现再定，与 Phase 2A 路由 SFT **衔接**而非重复）。
