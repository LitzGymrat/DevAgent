# DevAgent · 项目演进与成果展示

> 聚焦大代码库场景下的检索治理、数据构建与路由微调，以下展示核心设计与量化结果

**更新时间**：2026 年 3 月  
**核心成果**：工具调用一致率 97.8%、Phase 2A 路由微调 decision_type 一致率 98.0%

## 🎯 核心工作

### 1️⃣ 检索策略调整

#### 问题
早期模型在通用问答中容易过检索，不该查库时也会触发 `search_codebase`。

#### 解决方案

**软熔断（Soft Fusion）机制**
- 基于 Dense 距离分桶和阈值分析
- 对无效检索做兜底拦截
- 阈值 T=1.12 可拦截 62% 域外样本

**Prompt 调整**
- 根据端到端 bad case 迭代 system prompt 与工具描述
- 重点优化"是否调用工具"的判断逻辑
- 提高了工具调用的精准度

#### 📊 量化结果

| 指标 | 改进前 | 改进后 | 提升幅度 |
|------|--------|--------|---------|
| **工具调用一致率** | 63.3% | **97.8%** | +34.5% |
| **假正例（FP）** | 33 | **2** | ↓ 94% |
| **假负例（FN）** | 0 | **0** | ✅ 保持 |

> 对于必须查库的 35 条 must_ground 样本，两版测试的 FN 都为 0，说明 Prompt 优化未引入遗漏

- **评估内容**：检索后的软熔断效果
- **关键指标**：距离分桶准确率 ✅ **62%**
- **相关文档**：[评估/08-软熔断Phase1与端到端评测.md](../评估/08-软熔断Phase1与端到端评测.md)

- **评估内容**：LLM-as-Judge 按 bucket + grounding_tier 评估最终回答质量

### 3️⃣ 大仓库场景与数据飞轮

#### 外部仓基准建立

在 `experiments/external/` 中使用真实外部仓库建立基准：
- **Transformers** - 大规模深度学习库
- **FastAPI** - Web 框架
- 其他开源项目

#### 索引隔离

- 外部仓基准与主仓 `src/` 索引完全隔离
- 避免将主仓结果当成大仓表现
- 保证评测的准确性和可信度

#### 数据组织体系

数据按照使用场景组织，覆盖"该查库"和"不该查库"两类任务：

| 数据桶 | 样本数 | 说明 | 用途 |
|--------|--------|------|------|
| **domain**（私域） | 40 | 主仓相关任务 | 衡量域内准确率 |
| **far_general**（远域通用） | 28 | 线上排障、语法/算法基础 | 衡量过检索情况 |
| **term_near_no_rag**（术语边界） | 12 | 术语相近但不该查库 | 验证边界判断 |
| **misleading_edge**（误导边界） | 10 | 容易引起误导的边界情况 | 测试鲁棒性 |
| **总计** | **90** | | |

#### 数据处理流程

```
数据采集
  ↓
机器过滤（自动去重、质量检查）
  ↓
人工抽样复核（确保准确性）
  ↓
转为 ShareGPT 格式
  ↓
用于 LoRA 微调训练
```

### 4️⃣ 首轮 SFT：路由能力微调

#### 微调基座
- **模型**：Qwen2.5-7B-Instruct
- **方法**：LoRA（Low-Rank Adaptation）
- **数据**：50+ 多样化训练样本

#### 微调目标（Phase 2A 路由 SFT）

本轮聚焦三个核心指标，**不**将 arguments 与金标逐字一致作为主指标：

1. ✅ **JSON 可解析** - 输出必须是合法的 JSON
2. ✅ **决策类型正确** - `decision_type` 必须符合 gold
3. ✅ **工具名正确** - 调用的工具名必须准确

#### 📊 微调效果（50 条验证集）

**对比维度：Base（基线） vs LoRA（微调后） vs API（DeepSeek API）**

| 评估维度 | Base | **LoRA** | API | 提升幅度 |
|----------|------|----------|-----|---------|
| **可解析为 JSON** | 96.0% | **100%** | 100% | +4% |
| **JSON 结构合法** | 82.0% | **100%** | 98.0% | +18% |
| **decision_type 一致** | 56.0% | **98.0%** | 92.0% | 🏆 **+42%** |
| **工具名一致** | 86.7% | **96.8%** | 90.3% | +10.1% |

#### 🎖️ 核心成就

- ✅ JSON 结构合法率达到 **100%**
- ✅ decision_type 一致率提升至 **98.0%**
- ✅ 工具名一致率达到 **96.8%**
- ✅ 保持泛化能力（工具幻觉率仅 2.0%）

#### 📝 结论
首轮 LoRA 已经把路由决策和结构化输出做稳，后续可以继续往检索后生成和偏好对齐推进。

**详见**：[评估/11-Phase2A路由SFT微调报告.md](../评估/11-Phase2A路由SFT微调报告.md)

## 📊 核心指标快照

### A. 检索侧：距离分桶与软熔断（90 条样本）

#### 距离分布统计

| 分桶 | 样本数 | 均值 | 中位数 | 范围 |
|------|--------|------|--------|------|
| domain | 40 | 0.838 | 0.884 | 0.502–1.183 |
| far_general | 28 | 1.205 | 1.194 | 1.034–1.377 |
| term_near_no_rag | 12 | 1.055 | 1.133 | 0.638–1.334 |
| misleading_edge | 10 | 0.865 | 0.873 | 0.497–1.193 |
| **域外合并** | **50** | **1.101** | **1.156** | **0.497–1.377** |

#### 阈值标定结果

**阈值 T = 1.12**

| 指标 | 数值 | 说明 |
|------|------|------|
| 域外拦截率 | **62%** | 可拦截大部分域外查询 |
| 域内误伤率 | **7.5%** | 误伤小部分有效查询 |
| 推荐用途 | **兜底策略** | 适合作为二阶判断，不作为唯一判断 |

#### 💡 设计启示
- 域内与域外分布存在重叠
- 软熔断应搭配 Prompt 优化使用
- 不能仅依赖距离阈值进行判断

---

### B. 端到端工具调用一致率

#### 对比：首轮 vs Prompt v2

| 阶段 | 样本数 | 一致率 | FP（假正） | FN（假负） |
|------|--------|--------|-----------|-----------|
| **首轮（旧 Prompt）** | 90 | 57/90 (63.3%) | 33 | 0 |
| **Prompt v2（优化后）** | 90 | **88/90 (97.8%)** | **2** | **0** |

#### 关键发现

✅ **必须查库样本（must_ground：35 条）**
- 首轮：FN = 0（无遗漏）
- Prompt v2：FN = 0（无遗漏）
- **结论**：Prompt 优化未引入召回损失

✅ **假正例（FP）大幅降低**
- 从 33 条 → 2 条
- 降幅 **94%**
- **结论**：Prompt 优化有效拦截了过度检索
